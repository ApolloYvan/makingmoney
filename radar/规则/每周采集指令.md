# 每周采集指令（给 Claude）

每周日晚上，在 Claude 桌面端里打开这个仓库，把下面这句话发给 Claude：

> 请按 `radar/规则/每周采集指令.md` 跑本周的采集。

以下是给 Claude 的指令正文。

---

你在帮我运行"机会雷达"的第一阶段。它是我自己用来找生意方向的工具，背景和规则见仓库根目录的《机会雷达双Agent策划案.md》，第三到七节最相关。你这次的任务是：按来源清单找到本周的新信号，整理进数据文件，然后运行打分脚本生成周报。

你只负责找信息和整理信息。分数由 `radar/规则/score.py` 计算，你不要自己算分，也不要在任何文件里写分数。

## 必须遵守

1. 不修改 `radar/规则/` 目录下的任何文件。觉得规则有问题，写在最后的总结里告诉我。
2. 每条信号必须来自你这次真正打开过的页面。不要凭记忆或常识写信号。链接填你打开的那个页面的地址，原文摘录逐字照抄页面上的原话，不超过 100 字，不改写、不概括。
3. `数据/信号.csv` 只能在末尾追加新行，不能修改或删除已有的行。
4. `数据/验证.csv` 由我自己填，你不要动。
5. 所有"选项"类的字段，只能从 `radar/规则/打分规则.toml` 里列出的写法中选，一个字都不能差。拿不准就留空，并在总结里说明，不要猜。
6. 只读不需要登录的公开页面。不绕过登录、验证码或任何访问限制，遵守网站的 robots 规则，同一个网站不要短时间内反复请求。某个来源打不开，就记在总结里，不要换别的网站来顶替。
7. 来源清单里获取方式写着"我手动看""我手动查""我自己录入"的来源，你跳过，由我来处理。
8. 不要执行 git commit。我会先看 diff，再自己提交。

## 开始之前先读

- `radar/规则/打分规则.toml`：所有选项的合法写法。
- `radar/规则/来源清单.csv`：本周要查的是"一期"一栏为"是"的来源。信号的"来源"一栏必须和这里的"名称"完全一致。
- `radar/规则/不碰的事.md`
- `radar/数据/` 下的四个 CSV，了解已有的方向、信号和政策。
- `radar/周报/` 里最新的一期，它的文件名就是上次跑的周次。本次回看的范围是从上次那周的周一到今天；如果还没有周报，就回看最近 30 天。

## 步骤

### 1. 先处理新的访谈记录

`radar/访谈/` 下面，凡是还没有被 `信号.csv` 的"链接"一栏引用过的文件（以下划线开头的模板文件除外），都是新访谈。每份访谈至少整理出一条信号：来源填"线下访谈"，所属线填"经营压力"，阶段一般是"开始花钱"，链接填访谈文件的路径（如 `访谈/2026-10-12-五金加工.md`），原文摘录填对方的原话。访谈里提到每月花费或损失的，把金额折算成每月的人民币元数填进"金额元"，并在"备注"里写清楚怎么折算的。

### 2. 逐个来源查找新信号

按来源清单一个一个查。每条线要找什么，见策划案第三节（技术普及）、第四节（经营压力）、第五节（政策）。简单说：

- 技术普及：新能力、增长很快的项目、高频报错和求助、有人开始收费、大厂推出一键方案。
- 经营压力：哪些行业的回款、库存、成本在恶化；上市公司和投资者反复提到的经营难题；企业开始花钱解决的问题。
- 政策：新的规划、征求意见稿、正式文件、地方申报通知、处罚和专项行动。

每找到一条，在 `信号.csv` 末尾追加一行：

- 编号：接着已有的最大编号往下编，格式 S0001、S0002……
- 日期：信息本身的发布日期，格式 YYYY-MM-DD。页面上找不到日期的，填今天，并在备注里写"日期为发现日"。
- 来源、所属线、阶段：按上面的规则填。政策线的信号，"阶段"一栏填政策类型（发钱、加义务、撑腰、开窗、关窗）。
- 付费证据：只有快钱相关的信号才可能不是"无"。有人上架了相关服务或课程，填"服务或课程上架"；能看到销量，或者海外已经有人公开了收入，填"有销量或海外已验证收入"。
- 金额元：只有原文明确给出金额时才填，折算成每月的人民币元数，折算方法写进备注。

宁可少记，不要凑数。和"找生意方向"无关的信息不要记。

### 3. 把信号归到方向下

方向由三件事确定：什么新能力或什么压力、影响谁、他们遇到了什么问题。

- 新信号和已有方向对得上的，在"方向编号"一栏填那个方向的编号。
- 对不上、但本周有两条以上的信号指向同一件新事情的，在 `方向.csv` 里新建一个方向：编号接着往下编（D001、D002……），状态填"观察中"，类型填"快钱"或"长钱"。
- 只有孤零零一条、暂时归不了的信号，方向编号留空。

新建或更新方向时，各个分项只能从规则里的选项中选，每选一项都要在对应的"依据"一栏写明理由，并引用信号编号（例如"见 S0012：老板说每月追账要花两万"）。没有依据的分项留空。已有方向的分项，只有在出现新依据时才改，改了要在总结里列出来。"状态"一栏除了新建时填"观察中"，其他时候不要改，那是我的事。

"用不了"类的需求（比如境外模型在国内用不了）不要直接记成方向。按策划案第三节改写成合法的做法，比如"帮企业接入已备案的国产模型并做迁移"，再作为方向记录。

### 4. 检查不碰的事

对每个新建或更新的方向，对照 `不碰的事.md` 检查一遍。没有命中就在"命中不碰"一栏填"否"；命中了就填"第几条：理由"，例如"第一条：本质是帮人绕过访问限制"。同时填好"准入成本"和"准入成本依据"。

### 5. 更新政策

新出现的政策，在 `政策.csv` 里加一行，编号接着往下编（P001、P002……）。已有政策推进到了新阶段（比如从征求意见到正式发布），用同一个编号再加一行，填新的阶段和更新日期，不要改旧的那一行。阶段只能往前走。一条政策可以属于多个类型，用顿号隔开。

### 6. 每月第一个周日，额外做一件事

查国家统计局最新的工业企业财务数据和中小企业发展指数，找出回款、库存、成本这几项恶化最快的行业，写进 `radar/周报/YYYY-MM-行业压力.md`。表格里的每个数字都要附出处链接，并且照抄原文，不要自己换算。恶化明显的行业，各记一条"压力出现"的信号。

### 7. 检查并生成周报

在仓库根目录运行：

```
python3 radar/规则/score.py --check
```

如果报出的问题出在你这次新加的行上，就改正那几行（这是唯一允许修改已有行的情况：仅限你本次新加的行）。之前就存在的问题不要动，写进总结。然后运行：

```
python3 radar/规则/score.py
```

生成本周周报。

### 8. 最后给我一份简短总结

包括：每个来源各新增了几条信号；哪些来源打不开或者没查到东西；新建了哪些方向，改了哪些已有方向的哪些分项；哪些信号或分项你拿不准；有没有发现可能命中"不碰的事"的方向；你觉得规则有什么需要我调整的地方。
