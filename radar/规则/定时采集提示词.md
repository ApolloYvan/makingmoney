# 定时采集提示词（给 MUSE 等云端 Agent）

把下面分隔线之间的内容整段复制给 MUSE，作为每周定时任务的提示词。提示词本身每周不用改：具体规则都在仓库里，MUSE 每次运行都会读最新版本。

---

你每周帮我运行一次"机会雷达"的信号采集。所有规则都在 GitHub 仓库里，按下面的步骤做。

## 1. 准备

1. 仓库地址是 https://github.com/ApolloYvan/makingmoney ，用分支 master。本地还没有这个仓库就克隆下来；已经有了，就切到 master 并拉取最新内容。
2. 从 master 新建一个分支，名字是 `radar/采集-YYYY-Www`，用今天所在的 ISO 周，例如 `radar/采集-2026-W42`。
3. 确认 `python3 --version` 在 3.9 以上。

## 2. 采集

完整阅读 `radar/规则/每周采集指令.md`，从"以下是给 Claude 的指令正文"那一行之后开始，逐条照做。指令里说的"Claude"就是你。

有三处按这里的说明执行：

- 指令"必须遵守"的第 9 条：你是在云端运行，跑完要提交并推送到上面新建的分支，不要推送到 master，也不要合并。建分支、提交、推送只由你自己做；如果你把任务分给子代理，告诉它们不要执行任何 git 命令。
- 来源清单里获取方式写着"我手动看""我手动查""我自己录入"的来源，即使你能打开我授权给你的 App，也不要替我去看，直接跳过。
- 浙江省和杭州市的政府网站可能只接受中国大陆的网络访问。打不开就记为"打不开"并写明原因，不要用代理或其他方式绕过。

## 3. 收尾

1. 在仓库根目录运行 `python3 radar/规则/score.py --check`，问题数为 0 以后，运行 `python3 radar/规则/score.py --since 回看起点`，回看起点按指令里"开始之前"一节确定。
2. 只提交 `radar/数据/` 和 `radar/周报/` 下的改动，提交说明写"雷达：YYYY-Www 每周采集"，然后推送分支。如果发现自己改动了 `radar/规则/` 或其他目录下的文件，先撤回这些改动再提交。
3. 把指令第 8 步要求的总结发给我。总结开头写上分支名和本期周报的文件路径。

---

## 我怎么验收

每次跑完，按下面几条检查。第一次试跑全部通过，再设成每周定时运行。

1. GitHub 上多了一个 `radar/采集-YYYY-Www` 分支，master 没有变化；分支相对 master 只改了 `radar/数据/` 和 `radar/周报/`。
2. 周报最后的"数据问题"一节写着"没有"。
3. 随机抽 10 条信号看"价值判断"：谁、什么需求、钱在哪，三样都写得清楚；没有明显和赚钱无关的内容。
4. 总结里有一张表，写明每个来源看了多少条、记了多少条，打不开的有原因。
5. 周报里"待你确认的方向"每个都写了具体的付费方和要解决的问题，不同付费方没有混在一个方向里。
6. 政策只有两类：有申请门槛的企业或个人利好，以及新业态的放开。申报类的价值判断写了具体金额（或"通知未写金额"）和具体条件。
7. 总结里有一份犹豫清单，最多 10 条。

验收通过后，在 GitHub 上把分支合并进 master，下周的采集就会接着这周的数据往下编号。不通过的，把总结和周报发给我，一起看哪里要改。
