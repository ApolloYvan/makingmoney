# 视频转文字和总结

把视频变成文字稿，再按固定结构写总结。转写在本机完成，不用上传音频，也不用任何付费接口。

## 先确认在哪台机器上跑

B 站的视频服务器会拒绝云端机器和境外代理的下载请求（返回 HTTP 567 或 412），所以这一步要在用户自己的电脑（国内网络）上跑。

- 在用户的 Mac 上：直接运行下面的脚本。
- 在云端会话里：云端要靠代理上网，运行时加 `--keep-proxy`，可以先试一次。报 567 或 412 时不要换代理、伪造请求头或者用其他办法绕过，而是把下面"在 Mac 上运行"的命令交给用户，请他跑完把 `transcript.txt` 发回来，再接着写总结。

## 准备（每台电脑只需一次）

```
brew install yt-dlp ffmpeg
pip3 install faster-whisper
```

## 运行

在仓库根目录：

```
python3 .claude/skills/video-to-text/scripts/video2text.py "<视频链接或本地文件>"
```

脚本做的事：读视频信息 → 平台有字幕就直接用字幕 → 没有就下载音频，转成 16kHz 单声道 wav，用 faster-whisper 在本机转写 → 检查识别出的字数是否像样。最后一行打印文字稿的路径。输出放在 `~/Downloads/视频文字稿/<日期_标题>/`，包括 `transcript.txt`（每行带 `[分:秒]` 时间戳）和 `meta.json`（标题、作者、时长、播放量、用的是字幕还是转写）。

常用参数：
- `--cookies-browser chrome`：用本机浏览器里的登录状态，能拿到需要登录才给的字幕，也能解决部分下载被拒的情况。登录信息只在本机读取，不要让用户把 cookie 文件发给你。
- `--model medium`：识别更准，速度慢两三倍。专业名词多、`small` 识别得乱时用。
- `--keep-proxy`：脚本默认清掉终端里的代理设置，因为国内网站走代理常被拒绝；下载境外网站（如 YouTube）时加上这个参数。

出错时怎么办：
- 报 567 或 412：先确认代理已经关掉或者让这些网站直连（bilibili.com、bilivideo.com、bilivideo.cn、hdslb.com）；还不行就加 `--cookies-browser chrome`。
- 只识别出很少的字：换 `--model medium` 再试；视频本身是纯音乐的话，没有可转的内容。
- 终端里出现 `RuntimeWarning: divide by zero encountered in matmul`：这是 Mac 上新版 numpy 的已知提示，不影响结果，脚本已经屏蔽。
- 会员专享的内容不处理，不要尝试绕过。

## 写总结

完整读一遍 `transcript.txt` 再写，不要只看开头。语音转写会把同音字、人名、产品名、英文词识别错，按上下文改正；拿不准的写成"（转写可能有误：xxx）"，不要猜。

按这个结构写，存成文字稿旁边的 `summary.md`，同时在对话里给出：

```
# <视频标题>

<作者> · <发布日期> · <时长> · <播放量> · 来源：<字幕 / 语音转写>

## 一句话
这个视频讲了什么，结论是什么。

## 要点
按视频顺序列 5 到 10 条，每条后面标时间戳，例如（03:12）。

## 关键数字和说法
视频里提到的金额、营收、用户数、成本、价格等，逐条标时间戳。这些都是讲述者自己的说法，没有核实，写成"他说……"。

## 值得怀疑的地方
比如：数字说的是流水还是利润、有没有在卖课或者引流、有没有幸存者偏差、关键做法是不是一笔带过了。没有就写"没发现明显问题"。
```

如果用户在找赚钱的方向（比如在用 `radar/` 机会雷达），再加一节：

```
## 对我有用的信号
每条写清：谁（哪类人或企业）、什么需求、钱在哪（谁在付钱、付多少）。和雷达里已有的方向有关的，写上方向编号。
```

这一节只是给用户参考。视频是用户自己找来的，不属于雷达按固定方法采到的信号，不要直接写进 `radar/数据/信号.csv`，要不要记由用户决定。

## 注意

- 只处理公开视频，文字稿和总结只供自己研究，不要整段转发或者公开发布。
- 文字稿和总结默认留在 `~/Downloads/视频文字稿/`，不提交到仓库：文件大，而且是别人的内容。
